# Shipment Callback

> **Operational endpoint:** This callback is used by the shipment provider to notify Genzam IT about carrier, label, and tracking events. It is not a normal customer-facing API operation.

## Callback receiver

- **Endpoint:** `/callback`
- **Method:** `POST`
- **Authentication:** No bearer API key. The callback must include the configured callback token as a query parameter.
- **Example URL:** `https://api.genzam.it/api/v1/shipments/callback?token=CALLBACK_TOKEN`

The callback token is server-managed. Never publish the real token or include it in client-side code.

## Request body

```json
{
  "event": "shipment.tracking.update",
  "data": {
    "shipment_custom_reference": "OPTIONAL_CUSTOM_REFERENCE"
  }
}
```

### Supported events

| Event                        | Resolved state   |
| ---------------------------- | ---------------- |
| `shipment.carrier.success`   | `CARRIER_OK`     |
| `shipment.carrier.fail`      | `CARRIER_KO`     |
| `shipment.label.ready`       | `READY_TO_PRINT` |
| `shipment.label.fail`        | `LABELS_KO`      |
| `shipment.tracking.update`   | `IN_TRANSIT`     |
| `shipment.carrier.delivered` | `DELIVERED`      |

`event` must be one of the supported values, and the provider shipment identifier in `data` must be a non-empty string.

## Response

```json
{
  "handled": true,
  "state": "IN_TRANSIT"
}
```

Malformed payloads return `400`. An invalid or missing callback token returns `401`. Processing failures return `500`.

## Callback registration

The `GET /callback` route registers the configured callback URL with the upstream shipment provider. It has no bearer authentication and is intended for server operations only. Do not expose it as a general customer operation or call it from a browser.

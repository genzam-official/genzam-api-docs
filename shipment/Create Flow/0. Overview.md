# Shipment API: Create Flow

This guide explains how to build and create a shipment with the Genzam shipment API.

Start with the shared shipment details step, choose a carrier service, then complete the address and fulfillment details. International shipments that require customs also use the customs invoice step before the shipment is created.

## API configuration

### Base URL

All endpoints in this guide use the following base URL:

```text
https://api.genzam.it/api/v1
```

In the examples, this value is referenced as `${baseUrl}`.

### Authentication

Every request must include the API key in the `Authorization` header as a bearer token:

```http
Authorization: Bearer api_key
```

Replace `api_key` with the API key issued for your integration. Do not commit a real API key to source control or expose it in browser-side code.

### Request format

Requests with a body use JSON. Include the content type alongside the authorization header:

```http
Content-Type: application/json
```

## How to navigate

1. Open [Shipment Details](<1. Shipment Details Step.md>) and collect the origin and destination postal data.
2. Store the shipment draft returned by that step, including its `packages` and `additional_data` values.
3. Open [Carrier Services](<2. Carrier Services Step.md>) and send the draft location and package data to retrieve available services.
4. Select a service and keep its `service_id` in the shipment draft. The create endpoint derives `carrier`, `service`, pricing, currency, and source from that service ID; do not rely on client-supplied carrier or service names.
5. Choose one address flow:
   - Use [Address: pickup and delivery](<3. Address - Pickup-Delivery.md>) when the carrier collects the parcel from the sender.
   - Use [Address: drop-off and pickup](<3. Address - Dropoff-Pickup.md>) when the parcel is handed to a carrier drop-off point and collected from a pickup point.
6. For an international shipment that requires customs, complete [Customs](<4. Customs.md>) and add the returned customs invoice ID and status to the draft.
7. Send the completed draft to the matching [shipment creation endpoint](<5. Shipment Creation - Pickup-Delivery.md>), [drop-off and pickup endpoint](<5. Shipment Creation - Dropoff-Pickup.md>), or [customs shipment endpoint](<5. Shipment Creation - Customs.md>).

## Flow summary

```text
Shipment Details
      |
      v
Carrier Services
      |
      +--> Address: Pickup and Delivery ------> Create: Pickup and Delivery
      |
      +--> Address: Drop-off and Pickup ------> Create: Drop-off and Pickup
      |
      +--> Customs (international) ------------> Create: Customs
```

## Important conventions

- Keep the `packages` array and `additional_data.parcelIds` synchronized.
- Use the selected carrier service's `service_id`, `carrier`, and `service` values when creating the shipment.
- Use `collection_date` and `collection_time` for pickup flows.
- Use `dropoff_point_id` for drop-off flows; leave pickup-only fields unset as shown in the examples.
- Recalculate product prices after changing shipment contents, insurance, addresses, or service selection.

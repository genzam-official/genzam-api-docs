# Shipment API Overview

> **Note:** To call any API endpoint, the specific feature or endpoint must be enabled for your provided API key. Contact support if you encounter authorization issues.

---

## Authentication & Base URL

- **Base URL:** `https://api.genzam.it/api/v1/shipments`
- **API Key Required:** Yes. Contact Genzam IT support to acquire an API key.
- **API key example:** `sk_live_pN_VGG645R00h6USaC1XymEqB514003ek57gq_u8Q3E`
- **Feature access:** The required shipment feature must be enabled for the API key. Missing permissions return `403`.

---

## Headers

To authenticate requests, pass your API key as a Bearer token in the `Authorization` header:

| Header          | Value              | Description                                       |
| :-------------- | :----------------- | :------------------------------------------------ |
| `Authorization` | `Bearer <API_KEY>` | Bearer token containing your secret API key.      |
| `Content-Type`  | `application/json` | Required for `POST`, `PUT`, and `PATCH` requests. |

---

## Example Request

```bash
curl -X GET "https://api.genzam.it/api/v1/shipments/postal-zone?location=origins" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

## Common response and error format

Successful responses generally use:

```json
{
  "success": true,
  "message": "Operation completed successfully.",
  "data": {}
}
```

Validation errors return `400`. Authentication failures return `401`, missing feature permissions return `403`, and unexpected service or upstream errors return `500` with an `error` field when available.
